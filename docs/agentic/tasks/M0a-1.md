### What was built

- `crates/host-core/src/listener/identity.rs`: `TlsIdentity::generate(lifetime)` makes a self-signed ECDSA P-256 certificate (rcgen, `ring`) valid from now for `lifetime`, plus its PKCS#8 key and `fingerprint()` (raw `[u8; 32]`, SHA-256 of the cert DER). `fingerprint_base64url()` gives the `fp` text form. `save(tls_dir)` and `load(tls_dir)` use `cert.der` and `key.der`; the key is written with mode 0600 on Unix (and re-tightened if the file already existed). `load` rejects a key that does not match the certificate. `Debug` prints only the fingerprint. `server_config()` builds the rustls `ServerConfig` on the `ring` provider.
- `crates/host-core/src/listener/server.rs`: `start(config, &identity, tls_router, plain_router) -> ListenerHandle`. Binds through `bind_with_fallback(ip, port, attempts)`: the requested port, or the next free one; port 0 lets the OS choose. The accept loop spawns one task per connection. That task `peek`s the first byte, with a timeout, without consuming it. `0x16` → TLS handshake (with a timeout) → `tls_router`; any other byte → `plain_router`. HTTP is served by `hyper_util::server::conn::auto` (HTTP/1.1 and h2, with upgrades). Each request gets `Extension<Transport>` (`Tls` or `Plain`) and `ConnectInfo<SocketAddr>`. `ListenerHandle::shutdown()` stops accepting and drops the socket, so the port is freed. Open connections get a graceful-shutdown signal and `shutdown_grace` to finish, and are aborted after that. Dropping the handle also stops the listener.
- `crates/client-core/src/tls_pin.rs`: `pinned_client_config(pin)` (rustls `ClientConfig`, `ring`), `pinned_connector(pin)` (tokio-rustls) and `connect(addr, pin)`. The custom `ServerCertVerifier` compares the SHA-256 of the end-entity certificate to the pin with `subtle::ConstantTimeEq`. It does no CA or hostname check, and verifies TLS 1.2 and 1.3 handshake signatures against the presented certificate with the provider's algorithms. A mismatch becomes `PinnedTlsError::FingerprintMismatch` (`is_fingerprint_mismatch()`), and `PinnedTlsError::from_io` classifies tokio-rustls I/O errors. Other errors are `Tls(rustls::Error)` or `Io(io::Error)`.

### Tests (criterion → test)

- Pinned HTTPS works: `listener_pinned_client_completes_https_request`, `client-core handshake_succeeds_with_matching_pin`.
- Wrong pin gives the typed mismatch and the handler is never invoked: `listener_wrong_pin_fails_with_mismatch_and_handler_never_runs`, `handshake_fails_with_typed_error_on_mismatch`, `verifier_accepts_only_the_pinned_certificate` (first and last byte flipped).

- No hostname check: `verifier_ignores_server_name`.
- Plain GET reaches the plain service, and the transports never cross: `listener_plain_get_reaches_plain_service`, `listener_transports_never_cross`. Per-router hit counters are checked after each request, and the handler echoes the `Transport` and peer IP.
- Silent connection closed after the timeout without blocking others: `listener_silent_connection_is_closed_without_blocking_others`. Also, a stalled first byte or handshake does not delay other connections: `listener_stalled_tls_handshake_does_not_block_others`.
- Clean shutdown frees the port: `listener_shuts_down_cleanly_and_frees_the_port`, with an idle keep-alive connection and a silent connection open; `listener_dropping_the_handle_stops_it`.
- Taken port falls forward: `listener_taken_port_falls_forward_to_next_free_one`, `listener_requested_free_port_is_used_as_is`, `listener_bind_fails_when_every_attempt_is_taken`.
- Identity: `listener_identity_*`. Covers: fingerprint = SHA-256 of DER and its base64url form; self-signed, P-256, ecdsa-with-SHA256, validity span = lifetime (parsed with `x509-parser`, a dev-dependency); save/load keeps the fingerprint; key mode 0600, including the rewrite case; mismatched or corrupt files are rejected; `Debug` leaks no key or certificate bytes; an unrepresentable lifetime is an error.

### Defaults I chose

- The routers are `axum::Router` (axum 0.8, `default-features = false`, only the `tokio` feature in host-core; later tasks add `json` and others). HTTP is served by the hyper-util auto builder (HTTP/1.1 plus h2 prior knowledge, upgrades enabled). The TLS server sets no ALPN.
- `ListenerConfig::default()`: bind `0.0.0.0`, port 7420, 20 port attempts, first-byte timeout 10 s, TLS handshake timeout 10 s, shutdown grace 5 s. Fall-forward also skips `PermissionDenied`, because Windows reports some reserved ports that way.
- Identity files are `cert.der` and `key.der` (DER, so no `pem` feature). The caller passes the `tls/` directory itself; `TLS_DIR_NAME = "tls"` is exported. Only the key file is made 0600, and the directory keeps default permissions. The certificate has CN "Locale host" and no SAN; validity starts now and has no backdating.
- The pinned client does not check the certificate's validity dates (the spec pins by fingerprint only). The TLS server name sent is the host IP.
- There is no logging at all, so no key or certificate material can be logged.
- `base64` uses 0.23 (already in the lock). `time` was added because rcgen's validity fields are `time::OffsetDateTime`.
- `host-core` has `client-core` as a dev-dependency only, for the loopback tests.
