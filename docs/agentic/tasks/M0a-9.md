## Implementer notes

Crate and version: posthog-rs 0.33.1, released 2026-11-13 (CHANGELOG.md line 3 of the crate; cargo info shows no date). Read from ~/.cargo/registry/src/*/posthog-rs-0.33.1. No network calls to PostHog were made.

1. Capture
- Client types: async `client::Client` (src/client/async_client.rs:59) and blocking `client::Client` (src/client/blocking.rs:62), both re-exported from src/client/mod.rs:59-68.
- Calls: async `capture(&self, Event)` (async_client.rs:248) and blocking `capture(&self, Event)` (blocking.rs:236) are both fire-and-forget and return () once the event is queued; delivery errors are not returned (doc comment at async_client.rs:236-247). The blocking client also has `capture_immediate` returning CaptureSummary (blocking.rs:545).
- Batching: background worker, flush_at=100, max_batch_size=100, flush_interval_ms=5000 (src/client/mod.rs:296-313).
- Network down: capture reports nothing to the caller and the event is dropped after retries. Retry budget: `max_capture_attempts` defaults to 3 (src/client/mod.rs:280-284). In the default build (no `capture-v1` feature) the V0 path applies it (src/client/retry.rs:141-149). With `capture-v1` enabled, the V1 path applies it (src/client/v1_capture.rs:270, 311). `on_error` hooks fire on terminal failure (src/client/mod.rs:474-477).
- Capture-time timestamp: yes. `Event::set_timestamp` (src/event.rs:194-203) rejects future times beyond 1 s. Without it, the timestamp is stamped at enqueue (src/event.rs:309-311, src/client/transport.rs:184-186).

2. Disk persistence: NO. The queue is an in-memory worker buffer (max_queue_size=10000, src/client/transport.rs:161-168, src/client/mod.rs:313). A grep of src/ (outside mcp/) finds no file, SQLite or fs write for queued events. Unsent events are lost on process exit, apart from the best-effort shutdown drain bounded by shutdown_timeout_ms (src/client/mod.rs:313-326). The facade must own the SQLite queue.

3. Feature flags and remote config
- Remote: get_feature_flags, get_feature_flag, is_feature_enabled, get_feature_flag_payload (async_client.rs:814, 928, 1013, 1061; blocking.rs equivalents). Payloads are supported.
- Local evaluation: opt-in (enable_local_evaluation, default false, src/client/mod.rs:232-234). It polls flag definitions in the background. Without a secret key the blocking client logs a warning and falls back to API evaluation (src/client/blocking.rs:156-178). The secret key is used for local evaluation and remote config (src/client/mod.rs:204).
- Caching: the cache is FlagCache, a plain in-memory struct (src/local_evaluation.rs:108-114). It does not survive a restart; nothing is written to disk.
- Offline: remote calls return Error::Connection on transport failure (async_client.rs:810-812, 1051-1055, 1095). Callers must fall back to compiled defaults. feature_flags_request_timeout_seconds defaults to 3 and feature_flags_request_max_retries to 1 (src/client/mod.rs:260, 266). With local_evaluation_only=true and no cache, the crate returns Ok(None) instead of calling the network (src/client/mod.rs:270-278).

4. Configuration
- EU host: `.host("https://eu.i.posthog.com")` or `https://eu.posthog.com`, which is normalised to the ingestion host (src/endpoints.rs:7, 78-80; src/client/mod.rs:122, 130-133).
- distinct_id: yes, any string via Event::new(event, distinct_id) (src/event.rs:93). Event::new_anon generates a random distinct_id with Uuid::now_v7 and sets $process_person_profile=false (src/event.rs:116-127).
- Groups: yes, Event::add_group(group_type, group_key) (src/event.rs:176-182). It sets `$process_person_profile` to true (src/event.rs:177-180), which conflicts with digest §11 rule 5 (anonymous events, no person profiles). A caller that adds a group must then set `$process_person_profile` to false afterwards with insert_prop, or accept person profiles for group events. Groups are serialised as `$groups` in V0 properties (src/event.rs:451) and in V1 properties (src/event_v1.rs:45-50). The key is listed as correctness-required at src/event.rs:38.
- GeoIP: client-wide `disable_geoip` option (src/client/mod.rs:245-247). Per event, the property is `$geoip_disable` (src/constants.rs; src/event.rs:40).
- Person profiles: per event, property `$process_person_profile` set to false (see above; src/event.rs:39).
- Also: is_server defaults to true and stamps $is_server (src/client/mod.rs:253), which should be set false for client-side use.

5. Weight
- Direct normal dependencies (cargo tree --depth 1 -e normal): backtrace (optional, in default error-tracking feature; Cargo.toml.orig:24, 85), bytes, chrono, derive_builder, findshlibs (optional; Cargo.toml.orig:25, 85), flate2, os_info, regex, reqwest, semver, serde, serde_json, sha1, sha2, tokio (optional, default async-client; version "1" with features rt, sync, time, macros, Cargo.toml:310-316), tracing, uuid.
- HTTP client: reqwest. The manifest requires 0.13.2 (posthog-rs Cargo.toml:278-285, version at line 279; the original is Cargo.toml.orig:12). 0.13.5 is only the version that resolved locally.
- TLS: posthog-rs enables reqwest's `rustls` feature (Cargo.toml:278-285), and reqwest maps `rustls` to `__rustls-aws-lc-rs` (reqwest-0.13.5 Cargo.toml:169-173). So rustls means aws-lc-rs here. A caller can pass its own `reqwest::Client` (src/client/mod.rs:157) or `reqwest::blocking::Client` (src/client/mod.rs:186), which changes the client but not the build: aws-lc-rs stays because features are additive and posthog-rs always enables `rustls`. Ring is not in the normal tree, so a ring back end is not achievable with posthog-rs as published; that would need a fork or a plain-HTTP sender.
- Async runtime: tokio (see above); the blocking client does not need it.
- Heavier defaults: error-tracking (backtrace, findshlibs) is on by default; disable with default-features=false.

6. Recommendation
Use the crate for sending only, with the facade owning the SQLite queue and the flag cache. The crate has no disk persistence and no offline flag cache, so those two must come from the facade. Its aws-lc-rs TLS choice, not ring, should be accepted or the facade should send over plain HTTP instead.
