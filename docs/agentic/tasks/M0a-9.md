## Implementer notes

Crate and version: posthog-rs 0.33.1, released 2026-11-13 (CHANGELOG.md line 3 of the crate; cargo info shows no date). Read from ~/.cargo/registry/src/*/posthog-rs-0.33.1. No network calls to PostHog were made.

1. Capture
- Client types: async `client::Client` (src/client/async_client.rs:59) and blocking `client::Client` (src/client/blocking.rs:62), both behind the `client` module (src/client/mod.rs:59-68).
- Calls: `capture(&self, Event)` is fire-and-forget and returns once the event is queued (async_client.rs:236-247, returns ()). Blocking `capture_immediate` returns CaptureSummary (blocking.rs:545). Batching: background worker, flush_at=100, max_batch_size=100, flush_interval_ms=5000 (src/client/mod.rs:296-313).
- Network down: capture reports nothing to the caller. V0 transport retries up to max_capture_attempts=3 with backoff, then gives up (src/client/retry.rs:141-149); `on_error` hooks fire on terminal failure (src/client/mod.rs:474-477). Delivery failures are not returned from capture().
- Capture-time timestamp: yes. `Event::set_timestamp` (src/event.rs:194-203) rejects future times beyond 1 s. Without it, the timestamp is stamped at enqueue (src/event.rs:309-311, src/client/transport.rs:184-186).

2. Disk persistence: NO. The queue is an in-memory worker buffer (max_queue_size=10000, src/client/transport.rs:161-168, src/client/mod.rs:311-313). A grep of src/ (outside mcp/) finds no file, SQLite or fs write for queued events. Unsent events are lost on process exit, apart from the best-effort shutdown drain bounded by shutdown_timeout_ms (src/client/mod.rs:313-326). The facade must own the SQLite queue.

3. Feature flags and remote config
- Remote: get_feature_flags, get_feature_flag, is_feature_enabled, get_feature_flag_payload (async_client.rs:814, 928, 1013, 1061; blocking.rs equivalents). Payloads are supported.
- Local evaluation: optional (enable_local_evaluation, default false, src/client/mod.rs:234) with a background poller that needs a secret key. Definitions are held in an in-memory FlagCache (src/local_evaluation.rs:108-114). Nothing is written to disk.
- Caching: the last values are not persisted (FlagCache is a plain in-memory struct, src/local_evaluation.rs:108-114). The cache is in memory only, so a restart loses it.
- Offline: remote calls return Error::Connection on transport failure (async_client.rs:810-812, 1051-1055, 1095). Callers must fall back to compiled defaults. Feature_flags_request_timeout_seconds defaults to 3 and max retries to 1 (src/client/mod.rs:260, 266). With local_evaluation_only=true and no cache, the crate returns Ok(None) instead of calling the network (src/client/mod.rs:270-278).

4. Configuration
- EU host: `.host("https://eu.i.posthog.com")` or `https://eu.posthog.com`, which is normalised to the ingestion host (src/endpoints.rs:7, 78-80; src/client/mod.rs:122, 130-133).
- distinct_id: yes, any string via Event::new(event, distinct_id) (src/event.rs:93). Groups: yes, Event::add_group(group_type, group_key) (src/event.rs:176-182), sent as $groups.
- GeoIP: client-wide `disable_geoip` option (src/client/mod.rs:245-247). Per event, the property is `$geoip_disable` (src/constants.rs; src/event.rs:40).
- Person profiles: per event, property `$process_person_profile` set to false. Event::new_anon does this and generates a random distinct_id (src/event.rs:116-124; src/constants.rs).
- Also: is_server defaults to true and stamps $is_server (src/client/mod.rs:253), which should be set false for client-side use.

5. Weight
- Direct normal dependencies (cargo tree --depth 1 -e normal): backtrace (optional, default error-tracking), bytes, chrono, derive_builder, findshlibs (optional), flate2, os_info, regex, reqwest 0.13.5, semver, serde, serde_json, sha1, sha2, tokio 1.54.1 (optional, default async-client), tracing, uuid.
- HTTP client: reqwest 0.13.5 with features rustls, blocking, json, gzip, default-features=false (posthog-rs Cargo.toml).
- TLS: the rustls feature of reqwest pulls the aws-lc-rs provider (reqwest Cargo.toml: rustls = __rustls-aws-lc-rs), and posthog-rs hard-codes that feature. Ring is not in the normal tree. A ring back end is NOT achievable with posthog-rs as published, because its reqwest feature set cannot be changed by the app (features are additive). Using ring would need a fork or a plain-HTTP sender.
- Async runtime: tokio (rt, sync, time, macros) by default; the blocking client does not need it.
- Heavier defaults: error-tracking (backtrace, findshlibs) is on by default; disable with default-features=false.

6. Recommendation
Use the crate for sending only, with the facade owning the SQLite queue and the flag cache. The crate has no disk persistence and no offline flag cache, so those two must come from the facade. Its aws-lc-rs TLS choice, not ring, should be accepted or the facade should send over plain HTTP instead.
