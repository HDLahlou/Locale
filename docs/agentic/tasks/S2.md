Task S2: Write the toolchain probe behind `just doctor`: it prints a table of the build tools that are present or missing and exits non-zero when a tool needed for milestone M1 is missing.

Sections: python3 -I docs/agentic/tools/digest_section.py top 3

Context: The workspace skeleton exists (S1) and `just doctor` is a stub. Write the probe as one Python 3 script with no third-party packages, `scripts/doctor.py`, run as `python3 -I scripts/doctor.py`. It only looks; it never installs or changes anything and never uses the network. The build machine is macOS; the script must also run on Windows (the CI runner) and report Windows-specific items there.

Files in scope: `scripts/doctor.py`, `scripts/tests/test_doctor.py`, and the `doctor` recipe in the `justfile` (change only that recipe). Touch nothing else. If a file outside scope must change, stop and say so.

Acceptance criteria (all must hold):
- The script prints one row per check with: name, status (`ok`, `missing` or `warn`), the version or detail found, whether it is needed for M1 (`yes` or `no`), and a one-line fix hint when not `ok`. A final line gives the counts.
- Exit code 0 when every M1-needed check is `ok`; exit code 1 otherwise. Missing tools that are not needed for M1 never change the exit code.
- Checks, with "needed for M1" in brackets: `cargo` and `rustc` [yes]; `rustfmt` and `clippy` components [yes]; Rust targets `aarch64-apple-ios`, `aarch64-apple-ios-sim`, `aarch64-linux-android`, `armv7-linux-androideabi`, `x86_64-linux-android` [yes on macOS; the iOS ones are skipped on Windows]; `just` [yes]; `node` 20 or later [yes]; `pnpm` [yes]; `flutter` and `dart` [yes]; `flutter_rust_bridge_codegen` [yes]; `python3` 3.9 or later [yes]; on macOS, full Xcode selected (`xcodebuild -version` works) [yes], at least one available iOS simulator in `xcrun simctl list devices available` [yes], `sips` [yes]; Android SDK found through `ANDROID_HOME`, `ANDROID_SDK_ROOT` or `adb` on `PATH` [yes], an NDK directory inside it [yes], `adb` [yes], `emulator` and at least one AVD in `emulator -list-avds` [yes]; a JDK 17 or later [yes]; `cargo-ndk` [no]; `gh` installed and signed in (`gh auth status`) [no]; Playwright browsers installed for the workspace [no]; `libheif` discoverable through `pkg-config` [no; it is only bundled for Windows builds]; on Windows, MSVC build tools and the WebView2 runtime [yes on Windows]; free disk space at the repository of at least 20 GB [warn only].
- Each check is one small function returning a result record; the list of checks is data, so a later task can add one in a line. Every external command runs with a timeout of 20 seconds and a failure or timeout is reported as `missing` with the reason, never as a crash.
- `python3 -I scripts/doctor.py --json` prints the same results as a JSON array, for other tools to read.
- Tests in `scripts/tests/test_doctor.py` (standard `unittest`, run by `python3 -I -m unittest discover -s scripts/tests -t .`) run the script as a subprocess and prove: with a `PATH` that contains only a directory of fake tools made by the test, where a needed tool is absent, the exit code is 1 and that tool's row says `missing`; a missing not-needed tool leaves the exit code unaffected; a tool that hangs is reported after the timeout (use a short timeout override for the test); `--json` output parses and has one entry per check. The tests must not depend on what is installed on the machine.
- `just doctor` runs the script and passes its exit code through.
- Tests for every criterion are added and pass.
- No interface in crates/proto changes.

Verification: run `just doctor` (report its exit code and the rows that are not `ok`), `python3 -I -m unittest discover -s scripts/tests -t .` and `just check`; the last two must pass before you reply. Pipe long output through `tail -40`.
