- `sign_credential(payload, &ServiceSigningKey) -> Credential`; `verify_credential(text, &KeyList, now_ms) -> Result<CredentialPayload, CredentialError>` with `Malformed(&str) | UnknownKid | BadSignature | Expired | NotYetValid | WrongRole`.
- `sign_join_proof(&DeviceSigningKey, &EventId, &Fingerprint, ts) -> JoinProof`; `verify_join_proof(&payload, &proof, &EventId, &Fingerprint, now_ms) -> Result<(), ProofError>` with `BadSignature | Stale | Future`.

- `CREDENTIAL_CLOCK_SKEW_MS = 300_000`, `SECRET_KEY_BYTES = 32`.

**Verification order.** Structure (3 parts, `v1`, base64url, 64-byte signature, payload has a `kid`) → `kid` in list → strict signature over `v1.<segment as received>` → full payload decode (role other than `verified` → `WrongRole`, anything else → `Malformed`) → `expires_at <= now` → `issued_at > now + 5 min`. Proof: strict signature by `device_pubkey` over `proof_message()` → timestamp window via the existing `proof_timestamp_in_window` (inclusive).

**Strictness.** `VerifyingKey::verify_strict` (rejects small-order keys and `R`, non-canonical `s`). A mutation check (swapping to lax `verify`) makes the two small-order tests fail; those tests use a real forgery (identity key, `R = B`, `s = 1`) that lax verification accepts.

**Secrets.** Both key types wrap `ed25519_dalek::SigningKey`, which zeroes itself on drop with the `zeroize` feature (enabled; a test checks the workspace manifest keeps it). The seed buffer used by `generate` is cleared with `fill(0)` plus `black_box` (no `unsafe` available for volatile writes). Custom `Debug` prints kid and public key only; neither type implements `Clone`, `Serialize` or `Deserialize` (a compile-time ambiguity test fails if serde is added). Moves of the key can still leave stack copies; that is a Rust limit the crate cannot address.
