Task M0a-3: Build the image codec for macOS (ImageIO) behind one `ImageCodec` trait, with sniff, decode, facts, preview and compatible JPEG, and run it in a separate worker process with time and memory limits.

Sections: python3 -I docs/agentic/tools/digest_section.py top 3 4.4 4.5 8 10 12

Context: `crates/image-worker` is an empty library plus an empty `image-worker` binary. The host core will call it (task M2-3) to validate uploads and make previews, and (task M2-6) to make compatible copies; task M0a-4 adds the Windows back end behind the same trait and task M3-10 adds OS sandboxing, so keep platform code in one module per OS. The fixture images are in `fixtures/images/` with facts in `fixtures/manifest.json` (read the manifest's keys with a few lines of Python, not the whole file); the two 50 MB files appear in `fixtures/generated/` after `just fixtures-verify`. The location strip is a separate task (M0a-5) that will add `src/strip/`; do not write stripping code. The workspace forbids `unsafe`; ImageIO needs FFI, so this crate alone gets its own `[lints]` table with `unsafe_code = "deny"` (same clippy settings as the workspace), and `#[allow(unsafe_code)]` is permitted only on the macOS back-end module, with a `// SAFETY:` comment on every unsafe block. Prefer maintained binding crates (for example the `objc2` family or `core-graphics`) over hand-written declarations.

Files in scope: `crates/image-worker/**`, the `[workspace.dependencies]` table of the root `Cargo.toml` (alphabetical, one per line) and `Cargo.lock`. Touch nothing else. If a file outside scope must change, stop and say so.

Acceptance criteria (all must hold):
- A pure-Rust `sniff` module (no OS calls, usable on phones) classifies bytes as JPEG, PNG or HEIC/HEIF by magic bytes and, for ISO-BMFF, by an allowlist of `ftyp` image brands; everything else is rejected. Tests cover every file in `fixtures/images/`: `wrong_magic.*` are classified by content, not name, `heic_bad_brand.heic`, `not_an_image.jpg` and `empty.jpg` are rejected.
- An `ImageCodec` trait with a macOS implementation offering: full decode check (fail closed: any decoder error is an error); facts (`width`, `height` as the stored pixel size, `format`, `orientation`, `has_hdr_gain_map`); preview (JPEG, 1024 px on the long edge, never upscaled, EXIF orientation applied to the pixels, quality 80); compatible copy (JPEG, quality 92, full resolution, colour profile kept). On other operating systems the crate compiles and the codec returns a typed "unsupported platform" error; macOS-only tests are gated with `#[cfg(target_os = "macos")]`.
- The `image-worker` binary performs one job per process: it receives the job description and the input as an already-open file handle (for example the input file as stdin and a JSON job line as an argument or on a pipe), writes any output image to a path or handle given by the parent, prints one JSON result line, and exits. It never opens a network socket and opens no file by a path derived from image content.
- A parent-side API in the library (`Worker` or similar) spawns the binary for a job with a clean environment, enforces a time limit (default 10 s, configurable for tests) by killing the child, applies a memory limit of 1 GB where the OS supports one (say in the notes exactly what is enforced on macOS and what is not), and maps every abnormal end (non-zero exit, signal, timeout, malformed result line) to one typed error that callers will translate to `invalid_image`. The error carries only the format and a size bucket (`<5MB`, `5-20MB`, `20-50MB`), never a path or file name.
- Tests through the worker process, on macOS: `plain.jpg`, `plain.png`, `plain.heic` decode with the manifest's dimensions; each preview is a JPEG whose long edge is exactly 1024 px; the preview of `orientation6.jpg` has the rotated dimensions; the compatible copy of `plain.heic` is a JPEG at full resolution, and the compatible copy of `p3.jpg` still carries a Display P3 profile (check by reading the output back); `truncated.jpg`, `truncated.png`, `truncated.heic`, `wrong_magic.*`, `not_an_image.jpg`, `empty.jpg` and `heic_bad_brand.heic` all fail the decode check; `fixtures/generated/large_50mb.jpg` decodes within the time limit.
- Kill tests: a job that hangs (a test-only job kind compiled in only with a `test-util` feature or debug assertion, that sleeps) is killed at the timeout and reported as the typed error; a job whose child crashes (test-only abort) is reported the same way; after either, no child process is left running and no temporary output file remains.
- The parent locates the worker binary in a way that works in tests (`CARGO_BIN_EXE_image-worker`) and in a packaged app (a path given by the caller); there is no search of `PATH`.
- No `unsafe` outside the macOS back-end module. Nothing logs file names or paths.
- Tests for every criterion are added and pass.
- No interface in crates/proto changes.
