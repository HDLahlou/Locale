Acceptance criteria (all must hold):
- An `OsProbe` trait (name yours to choose) answers: network state (connected with a private address, hotspot on, or none), whether the firewall allows inbound connections on a port (`allowed`, `blocked`, `unknown`), free bytes at a path, power state (desktop, plugged in, or on battery with a percentage), and the three probes the reachability test needs (address class, mDNS peer reply within 2 s, connection to its own LAN address). A `FakeProbe` with settable answers lives in the crate behind a `test-util` feature or `#[cfg(test)]` plus a public test-support module, so the desktop and harness tests can reuse it.
- `run_capability_check(probe, request)` takes the storage allocation in bytes, the folder and the port, and returns one row per check (network, firewall, space, power) in that order, each `ok` or failed with a `reason` and a `fix_id`, plus an overall `can_start`. Rules from digest §4.2 step 4: network connected or hotspot on; firewall allows the port; free space at least the allocation; on a laptop, plugged in or battery above 50% (exactly 50% fails; a desktop always passes). `can_start` is false when any check fails. A firewall answer of `unknown` does not block but is reported as a warning row.
- Reasons and fix identifiers are closed enums with stable snake_case string forms (serde), for example reasons `no_network`, `firewall_blocked`, `low_space`, `low_power` and fixes `turn_on_hotspot`, `show_network_instructions`, `allow_firewall`, `choose_smaller_size`, `plug_in`. The network fix depends on the platform (hotspot on Windows, instructions on macOS), passed in as data, not read from `cfg!` inside the decision logic, so both are testable on one machine. The low-space row carries the free and required bytes.
- `run_reachability_test(probe)` implements digest §8 item 6 (DU-38) and returns exactly `ok`, `isolated` or `unknown`: `isolated` when the address is not private or is on a known captive or isolated range, or when the self-connection through the LAN address fails; `ok` when the address is private and either a peer answered mDNS or the self-connection succeeded; `unknown` otherwise (for example the OS does not allow the self-connection and no peer answered). The whole test is bounded by a timeout (2 s for the mDNS wait) using an injectable clock or tokio's paused time, so tests do not sleep.
- A fast variant for the quick session (digest §4.10 step 2) runs the same checks with the quick-session defaults (5 GB allocation) and the reachability test, and returns both results together.
- Table-driven tests cover every check passing and failing, each reason and fix pair, the 50% battery boundary, the free-space boundary (equal passes), both platforms' network fix, the `unknown` firewall warning, and every branch of the reachability result. One test uses the real probe for free space and port binding on the build machine (bind a port, check it is reported taken; a temp directory reports non-zero free space).
- No `unsafe`. Nothing here opens a firewall, changes a network or toggles a hotspot.
- Tests for every criterion are added and pass.
