Acceptance criteria (all must hold):
- One enum `EventName` with exactly the 21 events of digest §11, serialised in `object_action` form, and for each event a typed property struct holding only the properties the plan lists for it. Property types are closed: enums (reason codes and stages from `proto`, platform, client kind, access type, bucket enums), booleans, integers for timings in milliseconds and small counts the plan allows as exact, and nothing else. There is no `String` field and no free-form map anywhere in an event's properties, so free text cannot be expressed.
- Buckets as enums with constructor functions from the exact value: attendees `1-5`, `6-20`, `21-50`, `50+`; sizes `<5MB`, `5-20MB`, `20-50MB`, using binary megabytes consistently with DU-43; boundary tests at each edge. Exact attendee counts and exact file sizes cannot be put into any event.
- ID hashing: `event_group_id(event_id, salt)` returns a salted SHA-256 (lowercase hex) used as the `locale_event` group; the plain event ID never appears in the output. The install ID (`distinct_id`) is an opaque random value type created by the caller. Say which hash crate you add and why.
- Common properties added by one function: `app_version`, `platform` (`ios`, `android`, `macos`, `windows`), `client_kind` (`phone`, `desktop`), and the PostHog properties that keep events anonymous and turn GeoIP off (`$process_person_profile` false, `$geoip_disable` true).
- A consent type with two separate switches, usage data and crash reports, both default off. `prepare(event, consent, context) -> Option<OutgoingEvent>` returns `None` when usage consent is off; error and crash records are a separate type gated by the crash switch.
- `OutgoingEvent` is the only thing a sender may transmit. It serialises to a flat JSON object of allowlisted keys. A second, defence-in-depth function `filter_raw(name, json_properties)` takes untyped input (used for events coming from the Dart side) and drops unknown event names entirely and unknown or wrongly typed properties individually, returning what was dropped for a debug counter.
- The forbidden-properties test: feed `filter_raw` every forbidden kind from digest §11 rule 1 under plausible key names (photo bytes, preview, file name, hash, EXIF, post text, event name, plain event ID, description, link, display name, Wi-Fi name, IP address, GPS, exact attendee count, exact file size, free text), for every event name, and prove none survives; also serialise every typed event with representative values and assert the output contains only keys from the allowlist and no string value outside the closed enum values. This test is the one CLAUDE.md calls "the forbidden-properties test": name it `forbidden_properties_never_leave`.
- Unknown event names are dropped; `index_push_measured` sampling (1 in 20) is expressed as a pure function of a caller-supplied random number.
- Flags and remote-config names from digest §11 are already in `proto::config`; do not duplicate them. Reference them in the rendered contract's telemetry part.
- No `unsafe`, no async, no I/O. The staleness test for the generated contract passes after regeneration.
- Tests for every criterion are added and pass.
- No existing interface in crates/proto changes.
