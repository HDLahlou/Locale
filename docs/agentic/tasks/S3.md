### Open and closed enums

Open (unknown → `Unknown`, receive-only, serialises as `"unknown"`): `ItemReason` (unknown = final), `ChangeType` and `ChangeBody::Unknown { change_type, payload }` (raw payload kept), `ClientMessage`, `ServerMessage`, `ByeReason`, `NoticeKind`, `ReachabilityTestMode`, `CompatibleCopyStrategy` (unknown → compiled default). Closed: `AccessType`, `Role`, `SessionScope` (access), `ItemState` (state machine), `EventStatus`, `EventKind`, `ClientKind`, `PostKind`, `DownloadVersion`, `CredentialRole`, `JoinFailure`, `ApiCode`. The last two only travel as the string `error.code`, so an unknown code never breaks an error body. A known change type with a malformed payload is an error.

### Defaults I chose

1. Base64url is unpadded and canonical everywhere: join token is 22 characters, fingerprint and device key 43, signature 86.
2. The host code's separator is `" · "` (U+00B7 with spaces). The mDNS `fp` is the same 12 digits in uppercase with no separators.
3. `JoinUrl::parse`: the host must be an IP literal (IPv6 in brackets), the port must be present and not 0, the path is exactly `/e/<id>` with no trailing slash, and fragment keys may come in any order. Unknown fragment keys are ignored and a repeated `t` or `fp` is rejected.
4. Deep link: everything except RFC 3986 unreserved characters is percent-encoded. Other query keys are ignored.
5. `error.code` is a string. `received_bytes` for `offset_mismatch` sits inside the `error` object.
6. Join failure HTTP statuses: `wrong_password` 401, `token_invalid` 401, `removed` 403, `browser_not_allowed` 403, `event_ended` 410, `rate_limited` 429.
7. `retryable` is true only for these codes: join `rate_limited` and `unreachable`; API `rate_limited` and `offset_mismatch`.
8. `ItemState` wire values are uppercase (`"PENDING"`), as the digest writes them.
9. The guest session cookie is named `locale_session`.
10. Success statuses: JSON responses are 200, `POST /posts` returns 200 with a `Post`, and every DELETE (including `DELETE /uploads`) and `POST …/saved` returns 204.
11. In `upload_state` and `GET /submissions`, `reason_code` is `null` when there is none, `retryable` is `false` when there is none, and `item_id` is always present. In `POST /items` the `?` fields are left out when absent.
12. Snapshot items carry `download_count`, `hot_score` and `hot_score_updated_at` on top of the `item_available` fields (`SnapshotItem`). Without them a client could not sort by "Most downloaded" on join.
13. `Post.author_id` is `null` for system posts.
14. Event wire record fields: id, name, description (`""` when there is none), links (list of strings), starts_at, ends_at, expires_at, retention_hours, max_ends_at, extension_count, access_type, status, kind, host_display_name, browser_guests_allowed, storage_limit_bytes, created_at. The `event_updated` payload is `EventPatch`, which has the same fields, all optional.
15. `notice.expires_at` is optional, so an unknown notice kind still parses.
16. `Config` JSON uses the PH §7 keys: the five flags at the top level plus `transfer_config`, `outbox_config` and `rate_limits` objects. Missing keys take the compiled default. Join and password rate limits are fixed constants, not part of `Config`.
17. Bounds the digest does not give (it fixes only the chunk size): stall 30 s–10 min, transfer retries 1–10, backoff base 100 ms–10 s, outbox attempts 1–50, outbox age 1 h–7 d, uploads per window 1–1000, window 1–60 min.
18. Storage limits use binary units, extending DU-43: 20 GiB default and 5 GiB for a quick session.
19. Credential: the signature covers the ASCII bytes `v1.<payload segment>`. The payload JSON is compact, in declared field order. `decode` keeps the received segment so it re-encodes byte for byte. The signature must be 64 bytes and `device_pubkey` 32 bytes.
20. Proof: `proof` is `{timestamp, signature}`. The signed message is `"locale-join-v1"` (14 ASCII bytes), then the event ID (16 ASCII bytes), then the raw fingerprint digest (32 bytes), then the timestamp as Unix ms in an i64 big-endian (8 bytes), 70 bytes in all. The ±5 min window is inclusive.
21. Service auth: `PATCH /v1/account` and `POST /v1/host-link` use `Authorization: Bearer <refresh_token>`. Host-link takes no body and returns 204.
22. TXT: `st` and `en` are decimal ms and `v` is a decimal number. `from_pairs` ignores unknown keys, keeps the first of repeated keys, requires `access` to be `open` or `password`, and requires `fp` to be uppercase.
23. State table: reason codes have their own column, and the "Host on request" actor is `Actor::HostOnRequest`. In `is_legal`, `from` is `Option<ItemState>`, where `None` is "(none)".
24. IDs other than `EventId` are `String` aliases with no UUID validation.
25. Extra constants taken from listed sections: `TLS_FIRST_BYTE`, `HELLO_TIMEOUT_MS` 5000, `PREVIEW_JPEG_QUALITY` 80 (DU-14), `BROWSER_SESSION_TTL_MS` 2 h (DU-10), `MAX_INTEGRITY_ATTEMPTS` 3, `LOGIN_CODE_DIGITS` 6, `LOGIN_CODE_TTL_MS` 10 min, `POST_TEXT_MAX_CHARS` 500, `MAX_EVENT_LIFETIME_MS` 7 d.
26. `schemars` is a normal dependency rather than feature-gated, so the derive sits next to each type. It pulls in no runtime.
