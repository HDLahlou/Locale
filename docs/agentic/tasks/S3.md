Task S3: Turn digest §5–§7 into the `proto` crate: wire types, error and reason codes, change types, the credential format, the config struct, generated JSON Schema, and a contract document rendered from the code.

Sections: python3 -I docs/agentic/tools/digest_section.py top 5 6 7 10 11 12 13

Context: The workspace skeleton exists (S1); `crates/proto` is an empty library. This crate becomes the contract between host core, client core, the phone bridge and the account service, so every later task imports its types instead of writing its own; after this task only the orchestrator may change it. It is compiled into the phone app, so keep it small: no async runtime, no networking, no file or database access, no cryptography (credential signing and verification is task M1-2; the telemetry schema is task M1-17; both add modules here later). The host listener task (M0a-1) runs in parallel in `crates/host-core` and must not be touched.

Files in scope: `crates/proto/**`, plus the `[workspace.dependencies]` table of the root `Cargo.toml` (add entries in alphabetical order, one per line) and `Cargo.lock`. Touch nothing else. If a file outside scope must change, stop and say so.

Acceptance criteria (all must hold):
- Every endpoint, header, message and code in digest §5 has a type or constant, with the exact names, field names and string values the digest gives. Specifically:
  - §5.1: `EventId` (`evt_` + 12 lowercase hex, validated), `JoinToken` (128 bits, base64url), `Fingerprint` (32-byte SHA-256, base64url without padding; `host_code()` gives the first 12 hex digits uppercase as `4F2A · 9C1E · 77B0`; a constructor from raw digest bytes, since hashing happens in other crates), `JoinUrl` with `parse` and `Display` that round-trip `http://<host-ip>:<port>/e/<event-id>#t=<join-token>&fp=<cert-fingerprint>`, the default port 7420, the protocol version 1 and the `X-Locale-Proto` header name. Also the `locale://join?u=<url-encoded join URL>` deep link (DU-11), parse and format.
  - §5.2: the error body; one enum per code group (item reason codes including `duplicate`, join failures including the client-side-only ones, general API codes with their HTTP status); `retryable` for item reasons exactly as the digest lists.
  - §5.3: request and response structs for every row of the host API table; the route paths as constants or builder functions; header names (`Upload-Token`, `Upload-Offset`, `X-Locale-Sha256`, `X-Join-Token`); the rate-limit values.
  - §5.4: client-to-host and host-to-client WebSocket messages as enums tagged by `t`; the change envelope `{version, type, payload, ts}` with a typed payload per change type.
  - §5.5: request and response structs for the five account-service endpoints; the credential payload struct and the `v1.<base64url(payload JSON)>.<base64url(signature)>` text format with `encode` and `decode` that split and validate the three parts but do not check the signature; the exact bytes a proof of possession signs (`"locale-join-v1" ‖ event_id ‖ cert_fingerprint ‖ timestamp`) as one function, and the ±5 minute window as a constant. Where the digest does not fix a byte encoding (for example how the timestamp is encoded in the proof), choose one, document it in the contract document, and list it under "Defaults I chose".
  - §5.6: the mDNS service type and a TXT record struct with conversion to and from key-value pairs.
  - §6: enums for access type, event status, event kind, role, client kind, session scope, item state, post kind; record structs for the entities that cross the wire (event, attendee, item, post), shaped as the snapshot and change payloads need them. Database-only columns are not part of this crate.
  - §7: the item state machine as data: a table of legal transitions (from, to, trigger, actor, reason code if any, retryable) and a function `is_legal(from, to)`. A test checks the table has exactly the digest's rows and that every other pair of states is illegal.
  - §10 and §11: a `Config` struct with the tunable constants and flags, their compiled defaults and bounds, a `sanitize` step that ignores out-of-range values, and the fixed constants as `pub const`. Sizes use binary units: the maximum photo size is 52,428,800 bytes and the default chunk is 1,048,576 bytes (orchestrator decision DU-43).
- Enums that arrive from another device tolerate values this version does not know where that is safe (unknown change types and unknown WebSocket message types deserialise to an `Unknown` variant instead of failing); document which enums are open and which are closed.
- Round-trip serialisation tests for every type, using literal JSON written in the test from the digest (not produced by the code under test), so a renamed field fails a test.
- JSON Schema files are generated from the types into `crates/proto/schema/` and committed; a test fails when the committed files differ from freshly generated ones, and the failure message names the command that regenerates them.
- A contract document `crates/proto/CONTRACT.md` is rendered from the code (endpoints, messages, codes, state table, config defaults and bounds) by the same generator; the same staleness test covers it.
- No `unsafe`; public items documented; no dependency on tokio, any HTTP, TLS, database or crypto crate.
- Tests for every criterion are added and pass.
