Design rule from the orchestrator: the strip is size-preserving for every format. It overwrites or neutralises location bytes inside their existing segment, chunk or item and never moves any byte that follows them, because other structures point at absolute or relative offsets (HEIC item locations, the JPEG multi-picture table that locates an HDR gain map, TIFF offsets inside EXIF). After the strip, a parser must find no location data: for EXIF, the GPS IFD pointer is gone from IFD0 (not merely pointing at zeroed data) and the old GPS IFD bytes are zeroed; for XMP, the location properties are removed and the packet padded with whitespace to its old length; for IPTC, the location records are removed and the resource padded as the format allows, or their values blanked if it does not. PNG chunk CRCs are recomputed.

## Implementer notes

### What was built

Module `image_worker::strip` (`crates/image-worker/src/strip/`): `mod.rs` (API, plan/apply, private magic checks), `jpeg.rs`, `png.rs` (own CRC-32 table), `heic.rs`, `tiff.rs` (EXIF), `xmp.rs` (namespace-aware tag scanner, no XML library), `iptc.rs` (Photoshop resources and IIM), `rawprofile.rs` (ImageMagick hex raw profiles), `zlib.rs` (inflate with limit; deflate to an exact length).

API:
- `strip_location(&[u8]) -> Result<StripOutcome, StripError>`: `bytes`, `format`, `changed`, `kinds` (`exif`/`xmp`/`iptc`), `regions` (each container that held location data, with its kind and byte range).
- `strip_location_in_place(&mut [u8]) -> Result<StripReport, StripError>`: no second copy, for 50 MB files on a phone. The whole edit plan is built from the unmodified bytes first, so on error the buffer is untouched (tested).
- `scan_location(&[u8])`: a dry run that tests use to re-parse.
- `StripError`: `UnsupportedType`, `Truncated(Format)`, `Malformed { format, detail }`, `Unstrippable { format, detail }`.

How each format keeps its size:
- EXIF: the GPS pointer entry is removed from whichever IFD holds it (IFD0, IFD1 chain, Exif, Interop, SubIFDs). Kept entries move up, the count drops, the next-IFD pointer follows the last entry, and the freed 12 bytes are zeroed. Then the GPS IFD and its out-of-line values are zeroed, except bytes shared with kept IFDs, values or the IFD1 thumbnail.
- XMP: location elements and attributes are replaced by spaces in place. This covers main XMP, extended XMP (parts reassembled by GUID and offset, then written back), PNG iTXt, raw profiles and HEIC XMP items. Matching is by namespace URI, so any prefix works. Undeclared usual prefixes fall back to the standard URIs.
- IPTC: the location data sets are removed, the kept ones move up, and the resource is zero-padded. Photoshop resources that span several APP13 segments are read as one block.
- PNG: the changed chunk keeps its length and gets a new CRC. Compressed chunks (zTXt, compressed iTXt) are inflated (64 MiB limit), stripped, then re-deflated (miniz level 10, sync flush) and padded with stored blocks of spaces to the exact old length, with an Adler-32 over text plus padding. If the new stream cannot fit, the result is `Unstrippable`.
- HEIC: `ftyp` brand check, then `meta` (`hdlr` must be `pict`), `iinf` (infe v0–3), `iloc` (v0–2, methods 0 and 1, multi-extent) and `idat`. All Exif and `application/rdf+xml` items are overwritten in place (DU-37).
- JPEG secondary images: the strip follows images listed in the primary's MPF table and images concatenated after the primary's EOI. Each is walked to its own EOI.

`sniff` (M0a-3) is not in this checkout, so `detect_format` in `strip/mod.rs` holds the few magic checks privately: `FF D8 FF`, the PNG signature, and `ftyp` with a HEIF image brand. Swap in `sniff` once M0a-3 merges.

### Dependencies added
- `miniz_oxide` 0.8 (`default-features = false, features = ["with-alloc"]`), runtime. Needed to inflate and re-deflate zTXt and compressed iTXt raw profiles, which the brief requires. It is pure Rust with `#![forbid(unsafe_code)]`, and its only dependency is `adler2`. It was already in Cargo.lock (through `png`), so nothing new is downloaded. CRC-32 and Adler-32 are written by hand, so there is no crate for those.
- `serde_json` (dev only): reads `fixtures/manifest.json` in tests.
- `tempfile` (dev only, already a workspace dependency): temp directory for the macOS `sips` test.

### Error decisions per case (documented in `strip/mod.rs`)
- `empty.jpg`, `not_an_image.jpg`, `heic_bad_brand.heic` → `UnsupportedType`.
- `truncated.jpg|png|heic` → `Truncated(format)`. The JPEG hits EOF in scan data, the PNG has no IEND, and the HEIC `mdat` runs past EOF.
- `wrong_magic.jpg` (PNG bytes) and `wrong_magic.heic` (JPEG bytes) → `Ok`, unchanged. The strip goes by magic bytes only; the claimed-type mismatch is the precheck's job (M0a-3).
- A segment length below 2 → `Malformed`. A segment, chunk or box longer than the file → `Truncated`.
- IFD0 outside the block, an IFD whose entries overrun, broken XMP, an IPTC overrun, item extents outside the file, overlapping edits → `Malformed`.
- IFD loops and next or sub-IFD pointers outside the block end the walk; that data is unreachable, so it is not an error. A GPS pointer outside the block is still removed.
- Bytes after the last JPEG image, after PNG IEND, and a broken MPF table are ignored; none of these is location data.

### Defaults I chose
- XMP removal leaves spaces where the property was rather than padding before `<?xpacket end`. The packet length is the same and the XML stays well-formed. Extended XMP keeps its GUID: the MD5 is not recomputed, and the XMP toolkit matches parts by GUID without checking the digest.
- The IPTC resource is padded with zero bytes, which exiftool and the XMP SDK treat as the end of the data. The Photoshop IPTC digest (8BIM 0x0425) is left as it is.
- HEIF brands accepted: heic heix heim heis hevc hevx hevm hevs mif1 mif2 msf1, as the major or a compatible brand. This means an AVIF that lists `mif1` is accepted by the strip; the allowlist belongs to sniff.
- These fail closed with `Unstrippable`: XMP that is not UTF-8 (NUL inside), XMP with a DOCTYPE, HEIC metadata items that are protected, content-encoded, stored in another file, or built from other items (construction method 2).
- The EXIF thumbnail (IFD1 JPEG) is not parsed for nested metadata; only MPF and concatenated secondary images are.
- `exifEX:GPSHPositioningError` (CIPA namespace) is not on the brief's list, so it is kept.
