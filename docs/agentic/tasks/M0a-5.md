Task M0a-5: Write the location-metadata strip for JPEG, PNG and HEIC files: it removes location data only, never re-encodes, and leaves a file with no location data byte-identical.

Sections: python3 -I docs/agentic/tools/digest_section.py top 4.4 8 12 13

Context: The strip runs in two places: on the phone or desktop before upload (client precheck, digest §4.4 step 2) and again on the host (step 15), so it must be pure Rust with no OS calls and no `unsafe`, and compile for iOS and Android. It lives in `crates/image-worker` as the module `strip`, next to the pure-Rust `sniff` module from task M0a-3 (which may still be in progress in another worktree: do not touch `src/codec*`, `src/worker*` or `src/main.rs`; if `sniff` is not there yet, write the few magic-byte checks you need privately and note it). Fixtures are in `fixtures/images/` with facts in `fixtures/manifest.json`, including the synthetic location values to search for (read the keys you need with a few lines of Python, not the whole file). Decision already made (DU-20, DU-37): "original" means the file after this strip, and for HEIC the GPS data is overwritten in place so box offsets do not change.

Design rule from the orchestrator: the strip is size-preserving for every format. It overwrites or neutralises location bytes inside their existing segment, chunk or item and never moves any byte that follows them, because other structures point at absolute or relative offsets (HEIC item locations, the JPEG multi-picture table that locates an HDR gain map, TIFF offsets inside EXIF). After the strip, a parser must find no location data: for EXIF, the GPS IFD pointer is gone from IFD0 (not merely pointing at zeroed data) and the old GPS IFD bytes are zeroed; for XMP, the location properties are removed and the packet padded with whitespace to its old length; for IPTC, the location records are removed and the resource padded as the format allows, or their values blanked if it does not. PNG chunk CRCs are recomputed.

Files in scope: `crates/image-worker/src/strip/**`, one `pub mod strip;` line in `crates/image-worker/src/lib.rs`, `crates/image-worker/Cargo.toml`, `crates/image-worker/tests/strip*.rs`, the `[workspace.dependencies]` table of the root `Cargo.toml` (alphabetical, one per line) and `Cargo.lock`. Touch nothing else. If a file outside scope must change, stop and say so.

Acceptance criteria (all must hold):
- `strip_location(bytes) -> Result<StripOutcome, StripError>` (and a streaming or in-place variant if you judge it needed for 50 MB files on a phone) returns the output bytes and whether anything changed, with which kinds were found (`exif`, `xmp`, `iptc`). It handles JPEG (EXIF in APP1 including the GPS IFD and any GPS data in IFD1 or sub-IFDs, XMP in APP1 and extended XMP, IPTC in APP13), PNG (`eXIf` chunk, XMP in `iTXt`, and legacy `tEXt`/`zTXt` raw-profile chunks carrying EXIF, XMP or IPTC) and HEIC (the Exif item and any XMP item located through the `meta` box). It also strips metadata inside embedded secondary images of a JPEG (for example a gain-map image after the primary).
- Location data means: every tag in the EXIF GPS IFD; XMP properties `exif:GPS*`, `photoshop:City`, `photoshop:State`, `photoshop:Country`, `Iptc4xmpCore:Location`, `Iptc4xmpCore:CountryCode`, and the `Iptc4xmpExt:LocationCreated` and `LocationShown` structures; IPTC records 2:26, 2:27, 2:90, 2:92, 2:95, 2:100 and 2:101. Nothing else is touched: orientation, capture time, colour profile, HDR gain map and maker notes stay.
- The output length always equals the input length, and every byte outside the metadata segments, chunks or items that held location data is unchanged. A test proves this for each fixture by comparing byte ranges, which also proves the pixels are identical without a decoder.
- A file with no location data comes out byte-identical, with "changed = false": `plain.jpg`, `plain.png`, `plain.heic`, `orientation6.jpg`, `p3.jpg`.
- For `gps_exif.jpg`, `gps_xmp.jpg`, `gps_iptc.jpg`, `gps_all.jpg`, `gps_exif.png`, `gps_xmp.png` and `gps_exif.heic`: the output contains none of the manifest's synthetic location values in any encoding the fixture used (ASCII, EXIF rationals, XMP text); a re-parse finds no GPS IFD pointer, no XMP location property and no IPTC location record; the orientation tag and capture time are still present with the same values. The strip is idempotent: stripping the output again reports "changed = false" and returns identical bytes.
- On macOS, a test decodes input and output with the system (`sips` converting each to an uncompressed format in a temp directory) and compares the pixel data and the reported orientation and colour profile; they are equal. This test is gated to macOS.
- Malformed input never panics and never loops: truncated files, offsets pointing outside the file, IFD loops, zero-length and oversized segment lengths, and `not_an_image.jpg`, `empty.jpg`, `wrong_magic.*`, `truncated.*` and `heic_bad_brand.heic` each return a typed error or an unchanged result, decided and documented per case (a file whose type is not allowed is an error; a file whose metadata cannot be parsed safely is an error, so the caller fails closed). A property test or fuzz-style test feeds random mutations of each fixture and asserts no panic and that any successful output has the input's length.
- Device photos: a test reads `fixtures/manifest.json` and, for each device entry that is present, asserts the same properties (no location found on re-parse, same length, unchanged outside metadata, and for the HDR files the gain-map bytes unchanged). With no device files present the test passes and prints which files it is waiting for.
- The 50 MB fixture (`fixtures/generated/large_50mb.jpg`, present after `just fixtures-verify`) is stripped within 2 s in a release-mode test or benchmark; record the time in your notes.
- No `unsafe`, no OS calls, no new dependency heavier than a CRC or XML-free text scan needs; say why for each dependency added.
- Tests for every criterion are added and pass.
- No interface in crates/proto changes.
