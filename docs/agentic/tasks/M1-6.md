Acceptance criteria (all must hold):
- `GET /e/{event_id}/meta` on both transports returns exactly the contract's fields. `counts` is present only for an `open` event, or an `invite` event when `X-Join-Token` holds the valid token; never for a `password` event, whatever is sent. An unknown event ID is `not_found`; an ended event reports its status. No other field or header reveals anything from inside the event (attendee names, post text, item data). A test asserts the exact key set of the response for each access type.
- `POST /e/{event_id}/join` performs User Validation in the digest's order: rate limit, then an existing session if one is presented, then Access Validation: (a) `evaluate_identity` on the credential and proof (every failure means guest; the reason is written to the event log); (b) the access rule for the event's type: `invite` needs the valid join token, `password` needs the correct password even when a valid token is also sent (DU-9), `open` needs nothing; (c) not on the removed list. Token and password comparisons are constant-time. Failures return the contract's join failure codes and statuses: `token_invalid`, `wrong_password`, `removed`, `event_ended`, `browser_not_allowed`, `rate_limited`.
- Roles: `host` when the verified account equals the event's host account, `uploader` for any other verified account, `viewer` for a guest. A network join always has `is_host_device = false`. A separate in-process function, not reachable from any route, creates the host device's own attendee with `is_host_device = true`.
- Plain HTTP: only `client.kind = web` guests may join, only when the event is `open` or `invite` with browser guests allowed, always as `viewer` with a `read`-scope session of 2 hours, delivered in the body and as the `locale_session` cookie scoped to `/e/{event_id}` (HttpOnly, SameSite=Strict). A credential or a password in a plain-HTTP request is ignored or refused, never used. A `password` event over plain HTTP is `browser_not_allowed`. TLS joins by `ios`, `android` or `desktop` get a `full`-scope session of 12 hours; `kind = web` over TLS is refused.
- Roster: a join inserts or reuses the attendee row (unique per account or guest ID in the event; a re-join keeps the same attendee ID, updates display name and client kind, and issues a new session). Display names are trimmed and length-limited. Each first join appends an `attendee_joined` change through `changes::append` in the same transaction as the row; a re-join that changes nothing visible appends nothing.
- `changes::append(tx, change_body, now)`: the one function that writes the change log. It inserts the row with the next version, bumps `event.version` in the same transaction, and returns the version. After the transaction commits, the change is published on an in-process broadcast channel that the sync server (M1-7) will subscribe to; a rolled-back transaction publishes nothing. Tests cover gapless versions under concurrent joins and no publication on rollback.
- Sessions: 256 random bits, returned once, stored only as a SHA-256 hash, bound to attendee and event, with scope and expiry. `POST /session/refresh` returns a new token and expiry for a valid session and invalidates the old one. An expired or revoked session is `session_invalid`. Removing an attendee (a function for later tasks: sets `removed_at`, revokes all their sessions) makes their next join `removed` and their session invalid at once.
- A session check for later tasks: an extractor or middleware that resolves `Authorization: Bearer` (or the cookie on plain HTTP) to an attendee with role and scope in one indexed lookup, and helpers that require a role (`uploader`, `host`) or `full` scope, returning `role_denied` or `session_invalid`. Every write requires TLS and `full` scope: a test mounts a dummy write route and proves that a `read` session and any plain-HTTP request are rejected.
- Every request must carry `X-Locale-Proto: 1`; a different or missing version on the API routes is `proto_unsupported` (426).
- Rate limits from the contract's constants: joins 10 per minute per IP and password attempts 5 per minute per IP, with `retry_after_ms`, using an injectable clock; the limiter's memory is bounded.
- Event log rows are written for joins and denials (actor, client kind, result, reason) without storing a password, token or credential.
- A table-driven test covers every combination of access type (`open`, `password`, `invite`) × identity (verified host account, other verified account, guest, invalid credential, expired credential) × secret (right token, wrong token, no token; right password, wrong password, no password) × transport (TLS, plain) and asserts the outcome (role and scope, or the exact failure code). The table is written out in the test from the digest, not computed by the code under test.
- All tests run real HTTP over loopback through the listener, with a pinned TLS client for the TLS cases. Time and randomness are injectable. No `unsafe`.
- Tests for every criterion are added and pass.
- No interface in crates/proto changes.
