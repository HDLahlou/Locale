  - `plain.jpg`, `plain.png`, `plain.heic`: valid images with no location data, at least 1600 px on the long edge so a 1024 px preview is a real downscale; the HEIC made with `sips`.
  - `orientation6.jpg`: EXIF orientation 6, so tests can tell whether orientation was applied.
  - `p3.jpg`: carries a Display P3 colour profile, so tests can tell whether the profile is kept.
  - `gps_exif.jpg`, `gps_xmp.jpg`, `gps_iptc.jpg`, `gps_all.jpg`: location data in the EXIF GPS IFD, in an XMP packet (`exif:GPSLatitude` and `exif:GPSLongitude`), in IPTC location fields (city, sub-location, country), and in all three.   - `gps_exif.png` (an `eXIf` chunk with a GPS IFD) and `gps_xmp.png` (an XMP `iTXt` chunk).
  - `gps_exif.heic`: a HEIC whose Exif item has a GPS IFD (written through ImageIO).
  - `truncated.jpg`, `truncated.png`, `truncated.heic`: valid files cut at 60% of their length.
  - `wrong_magic.jpg` (PNG bytes with a `.jpg` name), `wrong_magic.heic` (JPEG bytes with a `.heic` name), `not_an_image.jpg` (text), `empty.jpg` (zero bytes), `heic_bad_brand.heic` (an ISO-BMFF file whose `ftyp` brand is `mp42`, not an image brand).
- Generated on demand into `fixtures/generated/` (ignored by git), deterministically and in pure Python so it also works on Windows, by `python3 -I scripts/make_fixtures.py --large`: `large_50mb.jpg`, a valid JPEG of exactly 52,428,800 bytes (the size limit), and `over_limit.jpg`, a valid JPEG of exactly 52,428,801 bytes. - `fixtures/manifest.json` lists every file with: `path`, `format` (`jpeg`, `png`, `heic` or `none`), `size_bytes`, `sha256`, `valid` (does it decode), `has_location` and which kinds (`exif`, `xmp`, `iptc`), `orientation`, `width`, `height`, `committed` (false for the two large files) and a one-line `purpose`. - `fixtures/device/README.md` tells a person exactly which four real photos to add and under which names (`iphone_hdr.heic` with an HDR gain map, `iphone_live_still.heic`, `android_ultrahdr.jpg`, `android.heic`), how to get them off the phone unconverted, and to run `python3 -I scripts/fixtures_verify.py --add-device` afterwards, which records their size and hash in the manifest. The manifest lists these four with `"source": "device"` and `"present": false` until then.
- `just fixtures-verify` runs `scripts/fixtures_verify.py`, which generates the large files if they are absent, then checks every manifest entry's size and hash, that no file in `fixtures/images/` is missing from the manifest, and, independently of the generator, that each `has_location` claim is true by parsing the metadata itself (EXIF GPS IFD present, XMP GPS properties present, IPTC location records present; for HEIC, the Exif item). Absent device files are reported as "waiting for a person" and do not fail the check. It exits non-zero on any mismatch and works on Windows (no `sips`).
- Tests in `scripts/tests/test_fixtures.py` (standard `unittest`) prove that the verifier fails when a file's bytes change, when a file is missing, when an unlisted file appears, and when a manifest claim about location is false; each test works on a temporary copy, never on the real fixtures. The tests do not create the large files.
- The location values used are obviously synthetic (for example 12.3456° N, 98.7654° E, city "Testville") and identical in every fixture, and are recorded in the manifest so later tests can search output bytes for them.
