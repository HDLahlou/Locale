## Implementer notes

Added `host_core::db` (EventDb, AppDb over one `Db` handle; migrations in `user_version`) and `host_core::event_folder`. Tests: `crates/host-core/tests/schema*.rs`. host-core now depends on `proto` (path) and `rusqlite` 0.37 bundled (workspace table), `thiserror`.

Defaults I chose:
- Attendee identity: two nullable columns `account_id` and `guest_id`, CHECK exactly one set, a unique index on each with `event_id`.
- Handle: `write` takes one mutex-guarded connection on the blocking pool, one transaction per closure (rollback on Err or panic). `read` opens a fresh read-only connection per call inside one read transaction (snapshot). Closures return the caller's error type `E: From<DbError>`.
- `change_log` gapless: `version INTEGER PRIMARY KEY` (rowid, max+1) plus an AFTER INSERT trigger that aborts when version differs from the row count. Deleting change_log rows is not blocked.
- `item.reason_code` CHECK allows NULL or the known `ItemReason` values (open enum; the host never writes `unknown`). CHECK lists are built from `proto` `ALL` at migration time, so a new enum value needs a new migration to widen existing files; the test lists the values literally so it fails when an enum grows.
- `hosted_event` is a single-row table (`slot = 1` CHECK) with event_id, folder, status (active or paused), updated_at.
- Booleans are INTEGER 0/1 with CHECK; `hot_score` is REAL; `links` and `config_json` are TEXT (JSON).
- `create_event_folder` creates `storage_path` if missing, fails if the folder exists, takes the ID as `&str` and validates it with `EventId::parse`. `index.sqlite` is created when `EventDb::open` runs. `delete_event_folder` succeeds if the folder is already gone.
- The newer-version check runs before the WAL pragma so a newer file is not changed.
