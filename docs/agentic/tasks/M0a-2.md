Acceptance criteria (all must hold):
- Host side (`host-core::transfer`): a chunk store that keeps one partial file per submission ID in a directory given by the caller, tracks `received_bytes`, appends a chunk only when the request's `Upload-Offset` equals `received_bytes` (otherwise 409 `offset_mismatch` carrying `received_bytes`, shaped as the contract says), rejects bytes beyond the size claimed for the submission, survives a connection that dies mid-chunk (a partly received chunk is either fully discarded or kept only up to bytes durably written, and the reported offset always matches the file), and reports completion when the last byte arrives. Handlers for `HEAD /uploads/{submission_id}` and `PUT /uploads/{submission_id}` as an `axum::Router` mounted under `/e/{event_id}`, streaming the body to disk without buffering a whole chunk in memory more than once. An authorisation hook is called before any byte is written.
- Client side (`client-core::upload`): given a file, a submission ID, the claimed size and an HTTP connection factory (pinned TLS), it sends chunks of the configured size (default 1,048,576 bytes), and on any failure asks the host for the offset with `HEAD` and resumes from there. The Retry Mechanism of digest §4.4 step 12: 3 attempts with exponential backoff and jitter from a 500 ms base, with the clock and randomness injectable so tests do not sleep; after the third failure it returns a typed "wait in the outbox" result with the last known offset. Progress is reported through a callback.
- Harness (`crates/harness`): a fault proxy, a local TCP forwarder placed between client and host, that can be told to cut the connection after N bytes in either direction, to stall, and to count bytes per direction and per connection. It works with TLS passing through it untouched. A helper starts a host listener with a given router on a loopback port and returns its address and fingerprint.
- Test `spike_resume` (in `crates/harness/tests/`, run by `cargo test -p harness spike_resume`): uploads `fixtures/generated/large_50mb.jpg` (create it with `python3 -I scripts/make_fixtures.py --large` in the test setup if absent) over pinned TLS through the proxy on loopback; the proxy cuts the connection at 3 pseudo-random points chosen from a seed printed on failure; the stored file's SHA-256 equals the source's; and the total bytes the client sent exceed the file size by less than one chunk per cut (no chunk is re-sent beyond the last partial one), measured by the proxy.
- More tests: wrong offset gives 409 with the right `received_bytes`; bytes beyond the claimed size are rejected and not stored; a cut exactly on a chunk boundary and a cut on the very last byte both resume correctly; the authorisation hook denying means zero bytes are written; three failures in a row return the "wait in the outbox" result after exactly three attempts with the expected backoff sequence; two uploads with different submission IDs at once do not mix bytes; a zero-byte claim is handled.
- No `unsafe`; no test sleeps longer than 100 ms of real time; nothing touches the network beyond loopback.
