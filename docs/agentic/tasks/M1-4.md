Acceptance criteria (all must hold):
- `create_event(app_db, request, now)` takes the digest §4.2 form: name, description, start, end, links, access type (`open`, `password`, `invite`), password (required for `password` events, refused otherwise), retention (0, 24 or 72 hours; default 24), browser guests allowed (default on; forced off for password events), storage allocation (default 20 GiB) and storage folder, plus the host's account ID and display name. It validates (non-empty trimmed name with a length limit, end after start, `expires_at = ends_at + retention` no later than `created_at` + 7 days, allocation above zero), then creates the event ID, a 128-bit join token, the event folder, the TLS identity in `tls/` valid for the event's maximum life, and the `event` row at version 1 with status `active` and kind `event`, and records it in `hosted_event`, all so that a failure at any step leaves no folder, no row and no pointer behind (test by injecting a failure after each step).
- `create_quick_session(app_db, host, now)` uses exactly the digest §4.10 defaults: name "<Host first name>'s session · <start time>", no description, links or times beyond `ends_at = now + 12 h`, access `invite`, browser guests on, `retention_hours = 0`, storage 5 GiB, `kind = quick`, `max_ends_at = now + 24 h` (the hard limit). The start time in the name is formatted from a time zone offset passed by the caller, not read from the system.
- One-active-event rule: a second create (event or quick session) while the app database points at an event that is `active` or `paused` is refused with a typed error carrying that event's ID and name; after that event is marked ended and the pointer cleared, create works again. A stale pointer whose folder no longer exists is cleared rather than blocking forever (say how you detect it).
- Passwords are stored only as an Argon2id hash with a per-event random salt in the standard encoded form; `verify_password` is constant-time through the library; the plaintext never appears in the row, the template, the join URL, `Debug` output or an error.
- `event_template` (in the app database): saved or updated when a full event is created, with only the fields digest §6 lists (never the password or its hash, token, key or host account); a quick session saves none.
- Join URL: `join_url(event, host_ip, port)` returns a `proto::transport::JoinUrl` that parses back to the same event ID, token and fingerprint; the password is never in it. `qr_image(join_url)` returns the QR code as an SVG string and as PNG bytes at a caller-given size, with a quiet zone, at an error-correction level you choose and state; a test decodes the generated QR back to the exact URL (use a pure-Rust decoder as a dev-dependency) for IPv4 and IPv6 hosts.
- Reopening: `open_hosted_event(app_db)` loads the pointed-to event with the same ID, token, key, fingerprint and port from disk (DU-17), and returns "none" when there is no pointer.
- Randomness (IDs, token, salt, key) comes from the operating system's secure source; tests that need fixed values inject them.
- Table-driven tests for every default and every validation rule; tests for every criterion are added and pass. No `unsafe`.
- No interface in crates/proto changes.
