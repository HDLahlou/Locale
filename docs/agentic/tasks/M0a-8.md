Acceptance criteria (all must hold):
- Host: `Advertiser::start(txt, port)` registers the service with instance name = event ID and the TXT pairs from `TxtRecord::to_pairs`, returns a handle, and unregisters on `stop()` or drop (a goodbye is sent). Re-advertising after a change of address or TXT content replaces the old record.
- Client: `browse()` yields a stream of events "found" (with the parsed `TxtRecord`, the resolved addresses and port), "updated" and "lost". Records whose TXT fails `TxtRecord::from_pairs` are ignored and counted, never surfaced. Browsing stops and frees its sockets when the handle is dropped.
- Two-process test (`cargo test -p host-core mdns`): a child process advertises a record; the test process browses, finds it within 5 s, and every TXT field equals what was advertised, including a name with non-ASCII characters and one at the TXT length limit; when the child stops, "lost" arrives. The same test with the roles swapped. Each run uses a fresh random event ID so parallel or repeated runs do not see each other's records.
- Unit tests that need no network: TXT building and parsing through the `proto` type, over-long names are truncated on a character boundary so the TXT entry stays within 255 bytes (say how), and malformed records are ignored.
- If the machine has no usable multicast interface, the real-network test fails with a message that says so plainly; it is not skipped.
- The mDNS crate is pure Rust and builds for iOS, Android, macOS and Windows; say which crate and why. No `unsafe`.
- Tests for every criterion are added and pass.
- No interface in crates/proto changes. If `TxtRecord` lacks something you need, stop and say what.
