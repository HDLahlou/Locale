## What each decision means for the build

**Q2. Contract.** Task S3 turns digest §5 into the `proto` crate without a review gate. After S3, the code is the contract: any change goes through the orchestrator, updates the digest in the same change, and is noted in the ledger.

**Q3. Windows.** Task S6 adds GitHub Actions workflows: macOS and Windows jobs for the Rust workspace and the image worker, and the guest-web tests. Until agents may push `ci/*` branches, a person pushes the branch, or Windows tasks wait. Windows-only code stays behind the `ImageCodec` and OS-helper traits, so macOS work never waits on Windows.

**Q4. Accounts service.**
- The code sender is a trait. A Postmark sender is used in production, a console sender in development and tests. Changing provider means one new file.
- Email needs a sending domain with SPF and DKIM records, and that domain must belong to you.
- The service's Ed25519 signing key is generated by a person and stored as a Fly secret. Agents only ever see the development key. Production public keys are compiled into host builds by `kid` (DU-31).
- The SQLite volume gets daily snapshots.

**Q7. Role labels.** `attendee.role` stays `host`, `uploader`, `viewer`. Labels: Host, Uploader, Guest. Use "Join as Uploader" or "Join as Guest", and "Guest · browser" in attendee lists.

**Q10. libheif.** Packaging (M3-16) marks Windows installers "internal testing". If the advice is negative, Windows hosts require the Microsoft HEVC extension instead, detected by the capability check.

**Q11. Identifiers.** Store identifiers are permanent once an app is uploaded, so `com.example.locale` must never reach TestFlight or Play. The `locale://` URL scheme (DU-11) stays.
