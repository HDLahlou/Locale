# Locale

Locale lets a person host a photo-sharing event from a laptop: guests join from a phone, the desktop app or a browser, and photos move directly between devices on the local network. A small account service handles sign-in and signed credentials but never sees event data or photo bytes. The host keeps every photo; the event ends when the host says so or it expires.

## Stack and layout

Rust core (host and client libraries), Tauri 2 desktop shell with React + TypeScript + Vite, one Flutter app (Riverpod) for iOS 16+ and Android minSdk 28 over the client core through flutter_rust_bridge, Rust account service with SQLite. Flutter 3.47.7 (stable, pinned at S1). Rust toolchain: stable (`rust-toolchain.toml`). pnpm 12.18 (pinned in `package.json`).

| Path | Purpose |
|---|---|
| `crates/proto` | Wire types, reason codes, telemetry schema. The interface contract |
| `crates/host-core` | Host: event API and socket, guest page, event index (SQLite), validation, previews, access control, sweeper |
| `crates/client-core` | Client: join, pinned TLS, local index and sync, outbox, downloads. Shared by desktop and phone |
| `crates/image-worker` | Image decode and convert worker process (library plus `image-worker` binary) |
| `crates/mobile-bridge` | flutter_rust_bridge API over the client core |
| `crates/harness` | Loopback test harness: host and clients in one process |
| `apps/desktop` | Tauri desktop app: `src/` React UI, `src-tauri/` Rust shell (`com.example.locale`, product "Locale") |
| `apps/web-guest` | Guest web page (React), embedded in the host binary. No CDN, no web fonts |
| `apps/mobile` | Flutter phone app (`locale`, `com.example`) |
| `apps/service` | App service binary (`service`): sign-up, sign-in, credentials |
| `packages/locale_media` | Flutter plugin: original-preserving picker, Save to Photos (Swift, Kotlin) |
| `packages/locale_net` | Flutter plugin: iOS Local Network permission, Android multicast lock (Swift, Kotlin) |
| `crates/telemetry` | Planned (M1-17b): telemetry facade: consent storage, offline queue, sender. The schema itself is in `crates/proto` |
| `packages/ui` | Shared web UI kit and design tokens (`tokens.json`, `labels.json`), pnpm member `@locale/ui`. Regenerate with `pnpm -C packages/ui generate` |
| `scripts/` | Developer scripts (`doctor.py`, `make_fixtures.py`, `fixtures_verify.py`), run as `python3 -I scripts/<name>.py`; tests in `scripts/tests` |
| `fixtures/` | Test images and `fixtures/manifest.json`. Committed files are never regenerated by tests; `fixtures/generated/` holds the two 50 MB files made by `just fixtures-verify` |
| `.github/workflows/ci.yml` | CI on `ci/*` branches: Rust on macOS and Windows, web, mobile, scripts |
| `docs/agentic/` | Build kit: spec digest, plan, ledger, tasks, tools |

`packages/locale_core` is generated by a later task; do not create it by hand.

## Conventions

- Timestamps are Unix milliseconds, UTC. IDs are UUIDv4 strings unless stated. JSON uses snake_case. Sizes are bytes. Hashes are lowercase hex SHA-256.
- Read the spec only through `python3 -I docs/agentic/tools/digest_section.py <selectors>`. Never read the Word files, the flow images under `flows/`, or the PostHog interview notes.
- Never edit `design/`, `docs/agentic/source/`, `docs/agentic/tools/`, `.claude/`.
- `crates/proto` is the interface contract; only the orchestrator changes it. `crates/proto/CONTRACT.md` is rendered from the code: read it instead of guessing a name.
- When you run a check, send its output to a file and print the exit code (`just check > out.log 2>&1; echo exit=$?`), then `tail` the file. An exit code read through a pipe is the pipe's, not the command's.
- Commit messages start with `<task ID>: `. Task notes go in `docs/agentic/tasks/<ID>.md`.
- Add dependencies only when code uses them. Shared versions live in `[workspace.dependencies]`; every crate sets `[lints] workspace = true`.

## Quality rules

- Every acceptance criterion has a test that fails without it.
- Tests never call external services. The account service, PostHog and email are faked; the harness runs host and clients on loopback.
- No test is weakened, skipped or deleted to make a build pass. A wrong test is fixed in its own commit with the reason.
- Telemetry goes only through the schema facade; the forbidden-properties test stays green.
- Nothing from inside an event is served before access validation passes (D17). Any change near join or `/meta` gets a test for this.
- Item state changes only through the state-machine module, with its change-log row in the same transaction.
